# Disasteronomy

A Godot **4.7 (Mono / C#)** 2D pixel-art, space-disaster themed co-op game built for a hackathon.
You are an astronaut doing a spacewalk: leave the airlock, follow the handrails to a frozen
cryogenic propulsion stage (CPS) and calibrate its stuck actuators before your tether gives out.

---

## 🛠️ Tech stack

- **Engine:** Godot 4.7.2 (Mono / C#), Forward Plus renderer
- **Language:** C# (.NET 8), with a little GDScript used for the networking autoload
- **Code editor:** `disasteronomy.csproj` / `disasteronomy.sln` (regenerated automatically by the Godot editor)
- **Target platform:** Windows desktop (`export_presets.cfg` presets included)
- **Netcode:** ENet multiplayer with LAN room discovery and voice chat

## 🚀 Getting started

1. Install [Godot 4.7 .NET](https://godotengine.org/) and a .NET SDK (8.0+).
2. Open the project: **Godot → Import → select this folder** (the `project.godot` is auto-detected).
3. Build the C# scripts: **Project → Tools → C# → Build** (or `Alt+B`).
4. Run the project from the editor (F5). The main scene is `res://Scenes/Intro.tscn`.

The `.csproj`/`.sln` are regenerated every time you open the project in Godot, so you don't need to
manage them by hand.

## 🎮 Controls

**Intro / cutscenes**
- Press `Enter` (or click/tap) to skip, using the on-screen **Skip [Enter]** button that fades in
  bottom-right. `IntroSkipButton` is a reusable scene/script (`Scenes/UI` + `Scripts/UI`); set
  `ShowSkipButton = false` on a cutscene to hide it.

**Main menu**
- `Start → New Game`, `Multiplayer`, `Options` (video + input remap with fade in/out), `Credits`.

**Phase 1 — EVA / Vacuum Calibration**
- `W A S D` / arrows — suit thrusters (inertia-based; no friction in space)
- **Hold left mouse** — extend the arm toward the cursor and grab a handrail
- `A / D` or `W / S` — slide along the rail you're gripping
- `Space` — SAFER jet (fires toward the cursor; pushes you the opposite way)
- `E` — calibrate at the CPS (spin the mouse to fill the 3 pins)
- `P` — pause · `F9` — debug teleport near the CPS

## 🪢 Rope / tether behavior (Phase 1)

The player starts tied to the airlock by a **tether (the "rope")**. Swinging only happens from your
own movement/input. Each time the swing reaches its **extreme** (the rope fully extended) it counts;
on the **3rd** extreme the rope **breaks** and the player switches to the **short-arm** state
(`RopeState.Rope → BrokenArm`), with a much smaller `arm_reach`. Leaving the map bounds restarts the
phase (resetting the extreme counter and rope state). All of this is tunable on `EvaPlayer`
(`max_extremes_before_break`, `tether_max_length`, `arm_reach`, ...).

The lobby and Phase 1 use the character-specific default sprites from `Sprites/Traje_Padrao`.
Phase 2 uses the protection sprites from `Sprites/Traje_Protecao`. The astronaut animations
(`float` = Idle, `grab` = Walk) are built into a `SpriteFrames` at runtime. You can override
the Phase 1 sprites by setting `SpriteFramesPath` to your own `.tres`/sprite resource.

## 📁 Project structure

```
project.godot          Engine config (input map, autoloads, main scene, HDR/nearest filtering)
disasteronomy.csproj   .NET project (regenerated by Godot)
export_presets.cfg     Windows Desktop export preset
Scenes/                Intro, MainMenu, MatchSetup (lobby), multiplayer, Phase1, Cutscenes/, Effects/
Scripts/
  Core/                Global (settings+save), SceneTransitions (fade), MusicManager, Sfx, PauseMenu, BriefingScreen, ...
  Effects/             Starfield, MouseParallax, SpaceshipMotion...
  UI/                  MainMenu, SettingsMenu, MatchSetup, MultiplayerMenu, IntroCutscene, IntroSkipButton, VoiceTutorial...
  Phase1/              Phase1Manager, EvaPlayer (rope/tether + SAFER), Handrail, CpsMinigame
  high_level_*.gd      ENet multiplayer handler + UI + spawner (GDScript)
Sprites/               Space suits, UI/menu art, cutscenes, character sheets
Music/                 Audio loops (SFX go in Music/sfx/)
```

**Autoloads** (in `project.godot`):
| Autoload | File | Purpose |
|----------|------|---------|
| `SceneTransitions` | `Scripts/Core/SceneTransitions.cs` | Fade transitions between scenes |
| `Global` | `Scripts/Core/Global.cs` | Video/audio settings, input remap, save/load |
| `Music` | `Scripts/Core/MusicManager.cs` | Menu music + volume |
| `HighLevelNetworkHandler` | `Scripts/high_level_network_handler.gd` | ENet multiplayer + LAN discovery |

## 🗺️ Phases

- **Phase 1 — Vacuum Calibration (implemented):** zero-gravity EVA, handrails, tether/rope with
  break-on-extreme, SAFER jets, and a CPS spin-the-mouse minigame. Reached by running
  `Scenes/Phase1/Phase1.tscn` (or from the menu via the intended flow).
- **Phase 2 — ISS Lab ammonia leak (planned):** 3-player duct work + rebooting software.
- **Phase 3 — dark MPLM maze (planned):** sanity bar + Orion capsule undocking.

## ⚙️ Included settings

- Input map: WASD/arrows, `Space`, `Shift`, left-mouse, `E`, `V` (voice chat) — rebindable in Options.
- Stretch mode `canvas_items`, shrink `1`; HDR 2D on
- Pixel-art friendly: nearest filtering, mipmaps off, anisotropic off, texture repeat off
- Audio bus layout with a **Microphone** bus + `AudioEffectCapture` for voice chat
- Reusable `Sfx.Play(node, "name")` helper — just drop files as `Music/sfx/<name>.ogg/.wav/.mp3`.
